Решения контроллера (2026-10-27):
- Логику restore вынести в handle-free `pub(crate) async fn` в `import_export.rs` (lock → guard → restore → post-import sync, возвращает `Result<String, AppError>`); tauri-команда и web-роут вызывают её. То же для create (filename из `backup_database_file`).
- Web-хендлеры работают с `AppError`, не со строками команд: `AppError::InvalidInput` → 400 `{ok:false}`, прочие → 500 `{ok:false}`. `../` в `:filename` (percent-encoded) → 400.
- Тест «delete во время restore» в web: delete не отклоняется, а ждёт lock (как в backup.rs:2880). Web-тест: параллельно два restore и delete того же backup (`tokio::join!`) — все ответы осмысленные (без паники/500 от join), итоговая DB открывается и содержит восстановленные данные. Строгий порядок уже закреплён тестами :251 и backup.rs:2880, их не дублировать.
- Периодический backup: общий `async fn` воркер (стартовая проверка + 24 ч), desktop `lib.rs` и headless (`bootstrap.rs` рядом с `spawn_session_usage_worker`, вызов из `examples/server.rs`) используют его; блокирующий `periodic_backup_if_needed` — через `spawn_blocking`. `start_background_checks` не трогать: это Stack-routing, фаза-владелец WEB-01 (ф.27–28) — записать в Notes.
